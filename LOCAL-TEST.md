## 1. Демо-файл без установки

Откройте `akty-demo.html` двойным щелчком (Chrome, Edge, Firefox, Яндекс Браузер). Интернет не нужен, шрифт встроен в файл.

* Сразу после открытия **объектов нет**: заведите их сами под `gc` или `client` (кнопка «Добавить объект»).
* Панель **ДЕМО** вверху:
  * переключение пользователя без выхода;
  * «+1 день» — сдвиг даты, чтобы проверить напоминания через 2 и 5 дней;
  * «Сброс» — вернуть исходные данные.
* Данные хранятся только в этом браузере. Другой браузер или режим «Инкогнито» начинает с чистого листа.
* Скачивание файлов (PDF, Word, ZIP) — это заглушки с корректными именами.

## 2. Полный стенд в Docker

1. Установите [Docker Desktop](https://docs.docker.com/get-docker/) и запустите его.
2. В папке проекта выполните:
   * Windows — дважды щёлкните `start-local.bat`;
   * macOS / Linux — `./start-local.sh`.
3. Первая сборка занимает 3–5 минут. Потом откройте **http://localhost:8080**.

| Команда | Действие |
|---|---|
| `start-local --demo` | пересоздать БД с **тестовыми объектами** во всех статусах процесса (заполнение, ожидание партнёра, проверка заказчика, проверка ГП, доработка, согласован, архив, изменение титула) |
| `start-local --reset` | пересоздать БД **без объектов** (пользователи и справочники остаются) |
| `start-local --stop` | остановить; данные сохраняются до следующего запуска |
| `docker compose -f local/docker-compose.yml logs -f app` | журнал сервера |
| `docker compose -f local/docker-compose.yml down -v` | удалить стенд вместе с данными |

Чтобы проверить работу нескольких участников одновременно, откройте второй браузер или окно «Инкогнито» и войдите под другим пользователем. Уведомления и чат обновляются автоматически.

> Пароли в `local/docker-compose.yml` тестовые. Для сервера используйте `deploy/` (см. `deploy/README.md`).

## 3. Без Docker (для разработки)

```bash
# PostgreSQL 17: база akty, пользователь akty/akty
cd backend
cp .env.example .env            # проверьте DATABASE_URL
npm ci && npx prisma migrate deploy
SEED_DEMO_OBJECTS=1 npx tsx prisma/seed.ts   # без SEED_DEMO_OBJECTS объектов не будет
npm run build && node --env-file=.env dist/main.js     # API: http://localhost:3000/api
# во втором терминале, из корня проекта:
npm ci && npm run dev:api       # веб: http://localhost:5173
```

Автотесты (сервер должен быть запущен, БД пересоздана с `SEED_DEMO_OBJECTS=1`):

```bash
cd backend
npx tsx test/api.e2e.ts         # 43 проверки API
python test/ui-api.py           # 17 проверок в браузере (pip install playwright)
```

## Что проверить — сценарий по шагам

**Подготовка (gc или client)**
1. Создайте объект: № п/п, название, адрес, округ, заказчик, общий объём, м².
2. Добавьте выполнение: период, титульный объём, м², подрядчики.
   * Сумма титулов выполнений не может превышать общий объём объекта.

**Подрядчики (mech, hand)**

3. Откройте «Мои объекты» → форму, добавьте виды разметки в **пог. м**.
   * Площадь в м² считается автоматически по коэффициенту вида разметки.
4. Загрузите PDF-схему и PDF-фото, нажмите «Подать форму».
   * Пока сумма не равна титулу, статус — «Ожидание партнёра».
5. Если один подрядчик закрыл весь титул, остальным автоматически подаются формы с нулями и без файлов.

**Заказчик (client)**

6. Когда сумма объёмов равна титулу, создаётся акт АОСР-NNNN и приходит уведомление «Требует действия».
7. Одобрите или отклоните каждую форму. При отклонении нужно указать причину, форма возвращается подрядчику.

**Генподрядчик (gc)**

8. Согласуйте акт или верните его на доработку. После возврата номер акта сохраняется, счётчик кругов увеличивается.
9. Выгрузите акт в Word (пока пустой шаблон) и скачайте все приложения в ZIP.
10. Отправьте акт в архив: кнопка «В архив» есть в карточке объекта и в карточке акта.
11. Корректировка после согласования доступна только ГП, с обязательной причиной. Она записывается в журнал, участникам уходит уведомление.
12. Измените титул после согласования — изменение подсвечивается, пишется в журнал, рассылаются уведомления.

**Общее**

* **Сводка:**
  * блок «Требует внимания» — изменения титула, отклонения, возвраты;
  * счётчики по этапам.
* **Уведомления:**
  * группировка по объекту и по типу;
  * фильтры;
  * кнопка «Отметить прочитанными».
* **Напоминания через 2 и 5 дней:**
  * в демо — кнопкой «+1 день»;
  * на сервере — администрирование → Настройки → «Проверить напоминания сейчас».
* **Администрирование (только gc):**
  * пользователи;
  * подрядчики;
  * заказчики;
  * виды разметки и коэффициенты;
  * допуск сверки.
* **Телефон:** откройте адрес стенда с телефона в той же сети (`http://<IP компьютера>:8080`). Меню открывается кнопкой ☰.

Замечания удобно присылать со скриншотом, логином пользователя и номером объекта или акта.
